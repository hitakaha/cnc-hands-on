Crosswork CNC Hands-on¶

This is the operator lab for Cisco Crosswork Network Controller (CNC) 7.1. You will use one shared controller and a Cisco Modeling Labs (CML) topology. Menu names follow the CNC 7.1 UI.

The room has one controller. A change you commit is visible to every seat. Use the seat number on the whiteboard in every name, color, and VPN id.

Storyline¶

You take the controller from a quiet maintenance state to a network you can see, explain, and change in a controlled way:

  1. Bring the controller and the CML lab up.
  2. Confirm the platform, the providers, and data collection.
  3. Read the topology.
  4. Read inventory, configuration, alarms, events, and performance.
  5. Compare a router-owned SR policy with a controller-owned SR policy.
  6. Provision one L3VPN and steer it onto that policy.
  7. Walk through Local Congestion Mitigation (LCM). The instructor owns any live commit.
  8. Tour Zero Touch Provisioning (ZTP) on screen.
  9. Ask the lab assistant one inventory question through the MCP server, then decide the next check yourself.

Suggested schedule¶

Two lab sessions, after the morning architecture briefing.

Session Chapters Intent
A 1 to 4 The network is visible and the devices are understandable
B 5 and 6 One SR policy and one L3VPN, with steering you can point at on the map
C 7 to 9 Congestion workflow, ZTP tour, assistant question

Chapters 1 and 7 start with an instructor action. Wait for that action before you click.

How to read each chapter¶

Each chapter has an objective, the clicks, the result you should see, and a short "done when" list. Router work in this lab is show output. Configuration changes go through CNC, and only in the chapters that say so.

What changed from the first outline¶

The nine chapters you listed are the lab. A few placements changed so the day matches CNC 7.1 and a shared CML lab.

  • CNC management includes providers and the Data Gateway. SR-PCE, NSO, and collection are the reason later chapters succeed. They belong with platform health, before the topology work.
  • Device configuration templates stay in the element-management chapter. In CNC 7.1 they live under Device Management. The NSO L2VPN and L3VPN function-pack templates are a different library. You meet those in the L3VPN chapter, when a provision action uses them.
  • SR-TE is observe-then-create. A PCC-initiated policy is already on a headend. You learn it from CNC. A PCE-initiated policy is the one you create, with your own color.
  • LCM stays in the outline, in Manual mode. CNC 7.1 can recommend tactical SR-TE policies when SNMP utilization crosses a threshold. A CML lab often shows 0% utilization, so a missing recommendation is a valid outcome. One instructor commits a recommendation if the data supports it. Students leave Automated mode untouched. Bandwidth on Demand is the fallback live demonstration when you want a PCE action and the links are idle.
  • ZTP stays a screen tour. The same rule covers image upload, serial-number enrollment, and template deployment.
  • The MCP chapter matches the assistant you have. The live question is the inventory count the server can answer. Remediation stays an operator decision. Session and write tools stay unused.
  • A checkpoint page collects the few failures that stop the room: maintenance still on, CML nodes down, provider unreachable, collection idle, NSO out of sync.

An L2VPN service is the same provisioning pattern as the L3VPN. This lab provisions one L3VPN so every seat finishes.
